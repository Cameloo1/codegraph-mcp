# Claims and Copy Guardrails

The visual system may be confident. Product copy must remain inside CodeGraph's public evidence contract.

## Strong, supportable language

Use language such as:

- local, proof-grounded repository context;
- deterministic typed program graph;
- graph and source verification;
- source-spanned evidence;
- compact context packets;
- exactness and confidence labels;
- candidate evidence remains labeled;
- read-mostly MCP;
- changed-file validation;
- unknown stays unknown;
- normal search, editing, and tests remain available.

## Language that requires qualification

### Real-time

Use only for the documented changed-file update primitive and watcher scheduling. Do not imply unsaved editor-buffer integration or a source-editing daemon.

### Semantic or vector

The current local candidate lane is deterministic and token-based. Do not describe it as learned production embedding quality unless the implementation and public contract change.

### Flow proof

State the eligible language and source-role slice. Do not imply equal micro-flow packet support across every registered frontend.

### Performance

Local footprint and timing numbers are examples from a documented environment. They are not guarantees or external benchmark comparisons.

### Language support

Say that extraction depth varies by language and extractor. A registered grammar is not a universal exactness or data-flow claim.

## Avoid

Do not write:

- prevents hallucinations;
- understands your entire codebase;
- compiler-grade verification;
- replaces tests;
- replaces `rg`;
- complete runtime understanding;
- works equally across every language;
- zero wrong edits;
- fastest code graph;
- proven SWE-bench improvement;
- industry-leading accuracy;
- production semantic embeddings, unless actually promoted and documented.

## Numbers

A number may appear only when it is:

1. a current public model or registry count;
2. a documented local measurement with its caveat;
3. a real value returned by the live product;
4. explicitly labeled as illustrative or sample data.

Do not generate fake confidence, latency, graph size, source-line, benchmark, user, or conversion values for visual texture.

## Recommended primary copy

### Product statement

> A verified map for coding agents.

### Supporting sentence

> CodeGraph turns a local repository into a typed program graph and returns source-spanned context before and after edits.

### Proof principle

> Vectors suggest. The graph verifies. Source spans support the packet.

### Relationship to normal tools

> Normal developer tools stay in the loop. CodeGraph adds typed paths, proof labels, source spans, and explicit unknowns.

## UI state language

Preferred:

- `No verified path matches the current query.`
- `Candidate context is available, but graph proof was not found.`
- `The configured graph is stale. Reindex before relying on proof paths.`
- `This relation is not supported for the current language frontend.`
- `Large graph truncated. Refine the relation filters or expand a selected node.`

Avoid:

- `Nothing found.`
- `The AI could not understand this.`
- `Probably safe.`
- `100% verified.`
- `Oops.`

## Review rule

Every public headline, diagram label, screenshot caption, social card, and product-site claim should be reviewable against the root README, current public docs, and promoted model metadata. If a claim depends on a raw report, local DB, benchmark run, or unpromoted branch artifact, omit it or label it as diagnostic.
